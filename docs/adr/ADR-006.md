# ADR-006 — No LLM in the decision loop

Status: Accepted

Date: 2026-09-22

## Context
LLMs in the core decision loop would make behavior non-deterministic,
untestable, and flaky — directly opposing ADR-005 and the project philosophy.
At the same time, "explaining" recorded device data in natural language is a
tempting future feature.

## Decision
- **Never use an LLM in the decision loop.** All creature decisions are
  deterministic functions of observable input + seed/clock.
- An optional local analysis layer (e.g., llama.cpp) is deferred far into the
  future, **feature-flagged and advisory-only**; the only sanctioned place is a
  Pokédex "explain like I'm 5" view over recorded data (post-M14, needs a
  ticket; PRD §0.8).
- New runtime deps (including inference libs) require justification per
  ADR-001 dependency policy.

## Consequences
- **Positive:** determinism (ADR-005) and testability are protected by policy;
  no cost/network dependence in the loop.
- **Negative:** no "smart" natural-language behavior in v1 — acceptable, out of
  scope by design.
- **Neutral:** keeps a forward-compatible path: advisory analysis can be added
  without touching core decision logic.
