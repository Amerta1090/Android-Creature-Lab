# ADR-004 — Storage: SQLite + JSON + JSONL

Status: Accepted

Date: 2026-09-22

## Context
The creature accumulates events, memory, and history; the Pokédex stores
config-shaped state, snapshots, and raw device observations. We need
queryable/transactional storage with zero extra dependencies and crash safety.

## Decision
- **SQLite** (`stdlib sqlite3`, WAL) for events, memory, and historical device
  model (queryable, transactional, crash-safe).
- **JSON** for state/config/snapshots — small, human-diff-able files under
  `data/`.
- **JSONL** for raw adb recordings — append-only streams feeding regression
  fixtures (A-005).
- Deterministic iteration and stable schema versions everywhere
  (PRD §G data model).

## Consequences
- **Positive:** zero-dependency stack, transactionality for memory/history,
  replayable recordings as fixtures, JSON state diffable in git/reviews.
- **Negative:** SQLite WAL needs a bit of process hygiene (checkpoints); JSON
  files must be written atomically (tmp + `os.replace` — already the config
  pattern, R-003).
- **Neutral:** one storage engine per concern keeps each file format small and
  debuggable.
