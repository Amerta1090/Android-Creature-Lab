# ADR-007 — Poll + edge events

Status: Accepted

Date: 2026-09-22

## Context
ADB offers almost no push channels that are stable across Android versions, so
"subscribe to device changes" is off the table at the v1 baseline. The
creature still needs timely reaction to what the user does on the device.

## Decision
- **Polling + edge detection**: cheap commands are polled on an **adaptive
  interval** — ~5 s while the device is active/foreground-app changes, ~60 s
  when idle (per-device configurable, config `devices.<serial>.poll_*`).
- **Transitions produce events** (PRD §H): observed state is compared across
  polls and the *edge* (change) is emitted as an event (`DEVICE_CONNECTED`,
  `APP_FOREGROUND`, `SCREEN_OFF`, …). The creature reacts to edges, not raw
  polls.
- Poll cadence is data (config), cheap commands first; logcat streaming is
  deferred to M14 as optional.

## Consequences
- **Positive:** resilient to ADB's lack of push channels; adaptive cadence
  bounds cost; event-driven core keeps the decision engine clean.
- **Negative:** worst-case reaction latency is one poll interval; "instant"
  events are impossible without investing in logcat (deferred).
- **Neutral:** recorded poll traces replay deterministically through the
  fixture transport (A-005), so edge detection is fully testable offline.
