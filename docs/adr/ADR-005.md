# ADR-005 — Determinism policy

Status: Accepted

Date: 2026-09-22

## Context
The project philosophy is "deterministic where practical": every decision a
creature makes should be reproducible so tests are stable and traces are
auditable. Wall-clock reads and global randomness destroy that.

## Decision
- **Injected clock** everywhere (`clock.Clock`, R-005): core modules never
  call wall-clock APIs; `SystemClock` lives at the adapter boundary and
  `SimClock` drives tests/sim. Banned API tokens (`datetime.now`, `time.time`,
  module-level `random`) are grep-checked by `make lint` (R-009).
- **Seeded RNG** (`rng.SeededRng`, R-006): one per creature, mixed with tick
  for per-tick stability; same (seed, tick) ⇒ identical stream across runs and
  processes.
- **Deterministic orderings**: sorted iteration, stable serials, no
  set/dict-order dependence in outputs.
- **Golden test files**: recorded fixtures replayed to pin expected behavior.

## Consequences
- **Positive:** reproducible decision traces (validated in M4), deterministic
  tests, replayable hardware observations.
- **Negative:** real-time wall behavior must be accessed through the adapter —
  a conscious indirection for every time-sensitive feature.
- **Neutral:** determinism is enforced by convention + lint (R-009), not by
  type system.
