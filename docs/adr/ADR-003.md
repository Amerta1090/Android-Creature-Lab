# ADR-003 — adb CLI wrapper

Status: Accepted

Date: 2026-09-22

## Context
How do we talk to the device? Options: a pure-python adb protocol library, or
wrapping the `adb` binary. The host already ships android-tools 37.0.0; a
library adds a dependency with TCP fragility and less transparent failure
modes.

## Decision
- **Wrap the `adb` CLI binary** via serial-targeted subprocesses
  (`adb -s <serial> …`), never global device select.
- All commands are **argument arrays** — no shell interpolation, no
  `shell=True` (PRD NFR-6); `adbc shell <cmd>` only for on-device commands.
- A typed `AdbResult(stdout, stderr, returncode, elapsed)` is the only surface
  parsers consume; timeouts (10 s default) and exit codes are honored; missing
  binary / transport / timeout / device map to `errors.AdbError` kinds
  (R-007/A-001).
- Recorded fixtures (JSONL) and a recording transport (A-005) let the stack run
  without hardware.

## Consequences
- **Positive:** stable, standard, transparent failures; deterministic and
  testable via mocks/fixtures; no new runtime dependency.
- **Negative:** depends on adb being installed/updated on the host; per-command
  subprocess overhead (mitigated by polling frugality, ADR-007).
- **Neutral:** adb version quirks are documented in Appendix A of the PRD and
  handled by tolerant parsers.
