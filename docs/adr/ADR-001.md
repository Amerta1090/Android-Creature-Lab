# ADR-001 — Python + stdlib-only runtime

Status: Accepted

Date: 2026-09-22

## Context
The project needs an implementation language and a dependency policy. The
runtime orchestrates `adb` subprocesses, parses JSON, and stores state in
SQLite — all well-trodden in Python — while staying maintainable at hobby
scale. Rust and Go were considered and rejected for slower iteration and
heavier tooling.

## Decision
- Implement in **Python 3.12+** (host has 3.14; `requires-python = ">=3.12"`).
- **stdlib + pytest only through M11** (PRD §0.10). Optional UX deps (`rich`,
  matplotlib) require a ticket + justification; a dev dependency needs the same.
- Packaging: `setuptools` with a `src/` layout and `creature`/`pokedex` console
  entry points (`pyproject.toml`).

## Consequences
- **Positive:** no build step, excellent test tooling, natural fit for
  subprocess/JSON/SQLite; any machine with Python runs `make setup && make test`.
- **Negative:** no compiled-language performance; ecosystem libraries stay
  off-limits until a ticket justifies one.
- **Neutral:** Locks the toolchain (`python3`, `pytest`) into the M0 baseline.
