# ADR-002 — Host-side runtime

Status: Accepted

Date: 2026-09-22

## Context
Where does the creature live? Two options: on the Android device itself (ship
an app, on-device storage, per-device install friction) or on the host PC with
ADB as the interface. The goal — a small autonomous software organism whose
*environment is the device* — favors keeping the device a pure subject.

## Decision
- The creature runs **on the host PC (the "Lab")**; the device never hosts
  application code.
- ADB is the only interface to the device; the device is observed and acted
  upon but never runs creature logic.
- Consequently, the device is identified by serial and its state is modeled as
  "what the device shows", not "what runs on it".

## Consequences
- **Positive:** no app shipping/install loop, no on-device storage to manage;
  the whole stack is testable without hardware via the fixture transport
  (A-005); all perception is reproducible by replaying recorded `adb` output.
- **Negative:** everything depends on the device being reachable via adb; a
  disconnected device means a paused/observing creature.
- **Neutral:** `creature` and `pokedex` are host-side CLI/binaries sharing the
  same runtime (PRD §K).
